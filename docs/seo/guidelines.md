## 0. 一句话

Google 不关心我们用不用 AI，也不关心内容来自谁；它只问一件事：**把这个作者的 prompt 放到我们站上，读者得到了原帖给不了的什么？** 答得出来，就是图库；答不出来，就是 scraping。

## 1. Google 明确会处罚什么

处罚有两种：算法自动降权，以及人工处罚（Manual action，会出现在 Search Console 的"人工处置措施"报告里）。后果是排名下降，或者整页乃至整站从结果里消失。

### 1.1 对我们风险高的（必须持续防）

| 政策 | Google 的定义（要点） | 我们最可能踩中的方式 | 我们的防线 |
| --- | --- | --- | --- |
| **Scraping（抓取转载）** | 转载他人内容却**没有加入原创内容或价值**；点名包括"专门嵌入或汇编其他网站的视频、**图片**等媒体、没有实质增值的站点" | 把 GitHub / X 上的 prompt 原样搬过来，配上作者的图，就算一页 | 每一页都要有原帖没有的东西：参数化选项、完整双语模板、我们自己的复现结果、编者说明（见第 2、3 节） |
| **Scaled content abuse（规模化内容滥用）** | 为了排名批量生成页面，**无论用什么方式生成**；点名包括用 AI 批量生成、**通过翻译**、同义替换等方式把抓来的内容改头换面 | 批量导入 prompt；用机器翻译一口气生成中英两套页面；给每个标签/关键词都做一个落地页 | 收录门槛看质量不看数量；译文要人工审校；不为关键词造页 |
| **Thin content（内容单薄，人工处罚）** | 低质量或浅薄的页面；常见形态是抓取内容和 doorway 页 | 详情页只有标题加 prompt 原文，没有任何上下文 | 详情页必须把"这是什么、要准备什么、怎么调、效果如何、谁写的、能不能商用"写在页面上 |
| **Doorway abuse（门页）** | 为一批相似搜索词造出一批**相似的页面**，"更像搜索结果页，而不是清晰可浏览的层级结构" | 为"赛博朋克头像 prompt / 动漫头像 prompt / …"各造一页，内容却是同一批卡片 | 筛选、排序、搜索页一律 `noindex,follow`（已实现）；只索引有真实内容差异的分类页 |
| **Structured data issue（结构化数据问题，人工处罚）** | 给**用户看不到的内容**加标记，或标记内容与页面内容不一致 | JSON-LD 里的 `description` 用的是页面上没显示的 `summary`；没做过的测试写进 `verifiedModels` | 结构化数据只描述页面上看得见的事实 |
| **Legal removals（法律移除导致的降权）** | 一个站收到大量有效的版权移除请求后，**站内其他内容也会被降权** | 收录了作者不同意公开的 prompt 或示例图，被投诉 DMCA | 许可状态如实标注；takedown 渠道随时可用、响应迅速；来源不明的一律不收 |
| **Hidden text（隐藏文字）** | 只给搜索引擎看、人看不到的文字；**仅对读屏器可见、用于改善无障碍体验的文字不算违规** | 首页和分类页的 H1 与介绍是 `sr-only`，代码注释写的是"留给爬虫" | 这段文字保持简短准确，不塞关键词；最好对人也可见（见需求 R6） |
| **Keyword stuffing（关键词堆砌）** | 不自然地重复关键词，**包括堆在 alt 里** | 在 alt、标签、`keywords` 里堆"AI prompt、midjourney prompt、chatgpt prompt…" | alt 描述画面本身；标签只保留真实维度 |

### 1.2 对我们风险低、但写清楚红线的

| 政策 | 红线 |
| --- | --- |
| **Malicious practices：劫持返回键** | 用户按返回键必须能马上回到来时的页面。现状合规：弹窗只在确认从本站列表打开时才 `router.back()`，切换选项用 `replaceState`，不会堆历史记录。以后改路由时守住这一点。 |
| **Misleading functionality（误导性功能）** | 不能声称能做到实际做不到的事。"在 ChatGPT 中打开"必须真的能带着 prompt 打开；不能暗示本站会生成图片。 |
| **Cloaking / Cloaked images（伪装）** | Googlebot 和用户看到的文字与图片必须一致；图片不能对搜索引擎和访客显示不同版本，也不能盖一层遮挡。 |
| **Link spam（链接作弊）** | 不和 prompt 作者搞"我收录你、你给我挂链接"的交易；不买链接；不在模板或页脚里向外批量铺关键词链接。作者自愿推荐我们没有问题。 |
| **Sneaky redirects（欺骗性重定向）** | 旧 slug 的 308、`/` 到 `/en` 的跳转都属于正当重定向；不按设备或 UA 跳转到不同内容。 |
| **Site reputation abuse（站点声誉滥用）** | 不适用：第三方 prompt 经过我们策展、改编，并以统一形式呈现，属于站点的一方编辑内容。前提是别把与图库无关的第三方内容（软文、联盟推广页）挂到站上来蹭权重。 |
| **Machine-generated traffic（自动化流量）** | 不写脚本批量查 Google 排名，要看排名就用 Search Console。 |
| **Expired domain / Hacked content / UGC spam** | 当前不适用：没有用户账号、没有上传、没有评论，投稿只走 GitHub issue。 |

### 1.3 AI 生成内容：Google 的真实立场

- **用 AI 本身不违规。** Rater Guidelines 原话的意思是：生成式 AI 既能做出高质量内容，也能做出最低质量的内容，花大量心思用 AI 创作的原创艺术作品同样可以是高质量的（§4.6.6）。这正好对应我们的示例图。
- **违规的是"没有增值的规模化"。** 无论文字、图片、音视频，只要主体内容几乎全部是复制、改写、嵌入或自动生成的，而且几乎没花心思、没有原创、没有增值，就判最低质量；**注明了出处也一样**（§4.6.6）。
- **Google 建议**：自动生成内容时，要说明内容是怎么产生的（"How"）；图片可以补充元数据（例如 IPTC `DigitalSourceType = trainedAlgorithmicMedia`，这一项只有 Merchant Center 强制要求）。
- **AI Overviews / AI Mode 没有额外要求。** 不需要 `llms.txt`、不需要专门的 AI 标记，页面能被索引、能显示摘要就有资格被引用。

## 2. Google 说的"写给人看、对人有用"的内容，放到我们这里长什么样

### 2.1 Google 的自检题，翻译成我们的问题

| Google 问 | 在 Prompt 详情页上意味着 |
| --- | --- |
| 是否提供了**原创的信息或分析**？ | 除了 prompt 原文，我们有没有加入自己的东西：参数化后能调什么、为什么这样拆、我们自己跑出来的结果是什么样 |
| 是否**完整**描述了主题？ | 读者不用再去原帖：需要准备什么输入（参考图）、在哪个模型上用、怎么调、预期效果、许可限制都在本页 |
| 如果引用了其他来源，是否**避免只是复制或改写**，而是提供了实质增值？ | 这正是我们的核心风险题（见 1.1 Scraping） |
| 标题是否是**描述性的摘要**，并且**不夸张**？ | "Photo + Abstract Memory Panel"是好标题；"最强爆款 Prompt!!"不是 |
| 读者会不会想**收藏、转发给朋友**？ | 分享链接能复原选项，这就是可以被分享的形态 |
| 是否**认真制作**，还是**匆忙粗糙**？ | 中英两版都完整、没有错别字、图片尺寸真实、alt 描述准确 |
| 读完之后，读者能不能**达成目标**？ | 复制 → 粘贴 → 附图 → 得到接近示例的图。做不到的场景要说出来（例如"需要支持参考图的模型"） |
| 是否由**真正懂行的人或爱好者**编写或审阅？ | 页面上要看得出是谁在挑、为什么挑，见 3.2 |
| 是否有**容易查证的事实错误**？ | 作者、链接、许可、日期、支持的模型，全部可以核对 |

### 2.2 一个"对人有用"的 Prompt 页必须回答的 7 个问题

1. **这是什么？** 一句话说明它能把什么变成什么（即 `summary`，而且要显示在页面上）。
2. **效果长什么样？** 真实示例图，并注明是作者产出的还是我们复现的。
3. **我要准备什么？** 是否需要参考图，需要什么样的图。
4. **怎么调？** 每个选项改变的是画面的哪一部分，选项名要让人看得懂。
5. **在哪用？效果可靠吗？** 我们实际测过的模型、日期和结果；没测过就明说没测过。
6. **谁写的？我能拿来做什么？** 作者署名并链接原帖，许可条款说清楚能否商用。
7. **我们改了什么？** 改编说明：格式整理、参数化、翻译，并声明这些不代表原作者的措辞或背书。

第 5 条和第 7 条是我们和"原帖搬运"之间最大的差别。

### 2.3 Who / How / Why：Google 要求能回答的三个问题

- **Who**：一眼就能看出是谁创作了内容。对我们来说是两层：prompt 作者（原帖与主页），以及策展人（谁挑选、谁改编、谁翻译）。
- **How**：内容是怎么做出来的。例如"根据作者的中英文原文整理格式并做了参数化""中文由维护者翻译并逐句校对""示例图来自作者仓库，本站尚未复现"。
- **Why**：为什么要做这页。Google 希望答案是"就算没有搜索引擎，我们的读者也需要它"。所以每一条收录都要能回答：为什么值得放进图库。

### 2.4 反面信号（Google 点名的"搜索引擎优先"内容）

- 为了追热点才收录，而不是因为觉得好。
- **凑字数**。Google 明确说过它不偏好任何字数。
- **只改日期不改内容**，假装内容是新的。我们的 `updatedAt` 只在内容有实质变化时才更新。
- 大量增删内容，想让站点显得"新鲜"。Google 明确说过这没用。
- 读完之后，读者还得再去搜一遍，才能真正用起来。
- 承诺一个其实没有答案的问题。比如写"支持 Midjourney"，却从来没测过。

## 3. E-E-A-T：四个字母分别是什么，页面上怎么体现

Google 说 E-E-A-T 本身不是一个排名因子，但它的系统会用一组信号去识别 E-E-A-T 强的内容。**Trust 最重要**，其余三项都服务于 Trust，而且不要求四项齐全（Rater Guidelines §3.4）。

我们不属于 YMYL（健康、金融、安全类）主题，所以对 Trust 的要求是中等，但**准确和诚实**这两条没有商量余地。

### 3.1 Experience（经验）：创作者有没有亲身用过

> 定义：创作者对该主题是否有**第一手或亲身经验**。Google 举的例子是：亲自用过产品的人写的评测，和没用过的人写的"评测"，你会信哪个？

**我们的对应问题是：这个 prompt，我们自己跑过没有？**

页面上的体现：
- 在作者示例旁边展示**"本站复现"结果**：用了什么模型、什么日期、什么选项，出了什么图。
- `verifiedModels` 只填真正测过的模型，并显示在页面上。
- 写出真实踩坑记录，例如"竖版比例下标题容易被裁切"。
- 没复现过就如实写"尚未复现"（目前的 `verificationNotice` 就是这么做的）。这条本身属于 Trust，不能省。

### 3.2 Expertise（专业）：创作者有没有相应的知识或技能

> 定义：创作者是否具备该主题所需的**知识或技能**。不同主题需要的专业程度不同。

**我们的对应问题是：我们懂不懂这个 prompt 为什么有效？**

页面上的体现：
- **编者说明**：这个 prompt 的结构是怎样的，哪一句控制构图、哪一句控制色彩，为什么要把某些部分拆成选项。
- 选项命名和说明要专业、准确，比如"照片 / 面板比例"就比"参数 3"好。
- 策展人简介：谁在挑、什么背景（About 页，外加详情页上一行署名）。
- 原作者的专业背景：链接到作者主页或仓库，让作者本人的作品集替他说话。

### 3.3 Authoritativeness（权威）：创作者或网站是不是这个主题的"首选来源"

> 定义：创作者或网站**是否以该主题的首选来源而为人所知**。大多数主题没有唯一的官方权威，但如果有，它通常最可靠。

**我们的对应问题是：别人提到"好用的生图 prompt"时，会不会引用我们，或者引用我们收录的作者？**

权威靠别人给，自己写不出来。页面上能做的是让权威可以传递、可以核对：
- 永远链接**原始来源**，并钉住具体版本（commit / 帖子 URL）。原作者本身就是这条 prompt 的权威。
- 可以核对的外部信号：开源仓库、署名、致谢页。
- 自然获得的外部链接：作者转发收录页、社区引用。**不能买，也不能交换**（见 1.2 Link spam）。
- 主题聚焦。Google 的自检题问"站点有没有一个明确的主要目的"。坚持只做生图 prompt，不扩展到无关主题。

### 3.4 Trust（可信）：页面是否准确、诚实、安全、可靠 ← 最重要

> 定义：页面在多大程度上**准确、诚实、安全、可靠**。如果页面因为任何原因不可信，E-E-A-T 就是低的，前面三项再高也没用。

页面上的体现（大部分我们已经在做，要守住，并且要**显示在页面上**，而不是只存在于数据里）：
- **来源真实**：作者、链接、许可、日期都可以核对，不知道的就填 `null`，绝不编造。
- **声明诚实**："示例由作者提供，并非实时预览""本站尚未复现""选项不是作者原话，也不代表作者背书"。
- **许可清楚**：能不能商用，用一句人话说明；示例图的版权单独说明。
- **下架渠道**：作者随时可以申请下架，入口在每页都能找到。
- **安全与隐私**：不上传图片、不调用模型、不收集输入内容；页面上没有欺骗性按钮。
- **结构化数据与页面一致**：JSON-LD 只描述页面上看得到的事实；不输出评分、评论、下载量。
- **日期诚实**：`dateModified` 只随实质修改变化。

## 4. 发布前自检（每条新 prompt 都要过）

- [ ] 这一页有原帖没有的东西吗？（参数化、完整双语、复现结果、编者说明，至少占两项）
- [ ] `summary`、所需输入、使用步骤、改编说明、许可说明都**显示在页面上**了吗？
- [ ] 示例图写清楚是作者产出还是本站复现了吗？`verifiedModels` 里的模型真的测过吗？
- [ ] 作者、原始链接、许可三项都能核对吗？
- [ ] 中文和英文都是完整、人工审校过的版本，没有删减吗？
- [ ] 标题描述准确、不夸张吗？alt 描述的是画面本身，没有堆关键词吗？
- [ ] 这条 prompt 是因为"它好"才收的，而不是因为"它热门"吗？
